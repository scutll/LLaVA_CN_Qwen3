## 扩展环节：实现中文多轮对话模型LLaVA-CN

​		完成了英文版多轮对话多模态大模型的解析，那接下来的想法自然是能不能自己去训练一个能够进行中文对话的大模型(实际上qwen就支持中文对话)。首先要做的就是要寻找**经过中文预训练的qwen模型，然后是中文的图文对话数据集、中文的图文多轮对话数据集**。

​		这里还有一个问题：要不要去寻找将图片信息转化为中文语义信息的CLIP版本，我的理解是不需要的，因为**CLIP将图片转化成的语义信息向量里面的信息是不分语言的，他就是一个信息向量，让它能被模型按中文或者是英文信息进行理解是语义对齐要干的事情**。

------

## 数据集寻找

- 由Intro中，CLIP并不需要寻找中文专用的模型，并且Qwen3本身也支持中文文本理解和生成，因此我们只需要寻找训练单轮对话stage1和多轮对话stage2的中文数据集即可
- 氮素格式差不多的中文数据集也太难找了，本身图文对齐的数据集就很少了，有图还有多轮对话的数据集就更少了。。。因此打算使用中文图文数据集先训练图文信息对齐能力，然后使用BELLEGroupe的多轮对话数据集(**没有图片，模拟人机之间的对话，一部分上句不接下句，一部分连起来是一个话题的那种，总之很接近平时人类会对ai干的事情**)来进行微调。并打算对比在使用图片和不使用图片的情况下多轮对话微调的训练效果(虽然语言，数据集大小都不同。。)
- 数据集：
  - 图文信息对齐能力：暂时找到两个coco数据集，但是数据集里面只有图片和描述，并没有问题
    - 实际上在用英文图文训练后，发现其实用中文提问时，也能正确的回答问题。所以当前的想法是**直接用经过stage1图文训练的模型进行微调，训练中文多轮对话的能力(闲聊)。**
  - 多轮对话能力：[BelleGroup多轮对话模型](https://huggingface.co/datasets/BelleGroup/multiturn_chat_0.8M/viewer?row=23&views[]=train)

## 微调环节

- 在英文数据集中，数据集都是有图片的，而这里我们使用只有文本的多轮对话数据集，因此打算使用了删去CLIP模块的纯qwen模型，但这样就无法加载stage1中的模型权重。所以**在新模型中，我们仍加上了CLIP模块，但在forward函数中不使用CLIP**，等到peft_inference中我们再使用CLIP就可以了

## 多轮对话

- 虽然使用模型只进行了多轮文字对话的训练，但我们的模型中仍有stage1两层线性层的结构，而导入的线性层权重也是经过训练的，可以直接导入使用。
- 这里我们**不再强制导入图片，而是可以选择导入与否**，若导入则将图片放在输入的最后。
- 修改：
  - 在model.py中将pixel_values设置为默认None，若无pixel_values则不进行图片处理
  - peft_inference中可以不修改，但单轮对话inference中需要进行修改
- 可以进行中文和英文的单轮对话了，在没有图片的时候也可以进行简单的对话，但还是感觉有点傻，**有时候会上句不接下句，或者突然忽略上一个话题(只要用户的回答有一点点跟当前话题无关或缺少提问成分)就直接转到问你其他话题(有可能是训练数据集对话轮次比较少的原因)**
- 接下来是**使用Topk来随机选择前k个可能的token，来增加ai回答的随机性**。有一个问题是可能很久都不能遇到<eos>，因此先测试不特别对待<eos>的情况，如果序列生成的过长，可以考虑若<eos>在k个token里面直接停止(但可能说一半就停止。。)，或者提高<eos>被选中的概率。
- 这里设置了三种token生成方式, 可以使用--Mode来进行选择：
  - Greedy每次选择最大概率token，TopkS使用top-k算法每次随机在k个可能性中选择，Hybrid在TopkS的基础上当遇到<eos>为最大概率时直接停止
  - 在不进行topK选择的时候，如果**用户的每句话都相同，那么模型给出的回复就每次都是完全一样的**
  - 但当使用topK进行随机选择，模型**就会给出每次都不一样的回答**，令人惊喜的是，模型**并没有因为topK的使用而出现突然<eos>使得对话戛然而止或者是因为没有<eos>而不能停止的情况（这是为啥，照理说应该会有不小心抽到<eos>而不小心随便就停止的情况。。）**
    - 也就是说，后两种token生成方式即使看着很不对劲，但大部分还是正常停止。。（反而搞不懂了）
